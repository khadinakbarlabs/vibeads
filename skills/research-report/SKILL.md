# Paid ads research report

Read [workflow rules](../ads/references/workflow-rules.md), [report template](../ads/references/templates/report.md), [ledger](../ads/references/templates/evidence-ledger.csv) and [coverage template](../ads/references/templates/coverage.csv).

1. Confirm the decision and intended reader. Use only evidence expressly supplied for this task or produced by its approved research runs. Do not scrape hidden project state or unrelated reports.
2. Lead with the recommended first test and why its evidence is stronger. Present competitor patterns, keyword candidates, creative directions, page requirements and budget/measurement choices only where relevant.
3. Link every factual recommendation to evidence IDs. Distinguish `observed`, `estimated`, `inferred`, `hypothesis` and `unknown`. If evidence is absent, provide a clearly labeled planning draft rather than simulated live records.
4. Include a per-source coverage table with platform, advertiser/market/date filters, requested/received count, capture time, run/build, status, dataset and summaries, cost verification and limitations. `not_requested` and `failed` are not zero competitor presence. Do not include private dataset URLs in a shareable report.
5. Include exact media-budget totals and units, separate research/production/software costs, confidence and dependencies. Reconcile the number of days and reserve. Public CPC/volume estimates do not establish account results.
6. Finish with concrete actions: owner, time, artifact, dependency, success check and approval needed. Present local validation, connected execution, host behavior, directory scan/review and publication as separate evidence states when reporting release readiness.

Create Markdown/CSV files only if the user asks for export and confirms the intended output location through the request. Do not upload or share them automatically. If a dashboard or chart would help, propose it using the host's available artifact tools and the same coverage labels.
